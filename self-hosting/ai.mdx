# AI Providers

TryPost's AI features are built on [Laravel AI](https://laravel.com/docs/13.x/ai-sdk) ([GitHub](https://github.com/laravel/ai)), the official first-party AI SDK for Laravel. Every provider and model on this page is whatever that package supports — TryPost doesn't add its own provider integrations on top.

TryPost uses the SDK for **text only**:

- the writing assistant in the composer (generate, rephrase, shorten, expand, more casual, more formal)
- generating ideas under **Create** > **Ideas**
- image alt text
- adapting captions in Repurpose

AI runs in the web app only — the REST API and the MCP server have no AI endpoints or tools. There are no credits or per-call limits; your provider bills you directly. New text is written in the language of the user who asks for it, and a rewrite (shorten, rephrase, change the tone) keeps the language of the text it rewrites.

```env
AI_TEXT_PROVIDER=openai
OPENAI_API_KEY=sk-...
```

| Variable | Description |
|----------|-------------|
| `AI_TEXT_PROVIDER` | `openai` (default), `anthropic`, `gemini`, `azure`, `bedrock`, `groq`, `xai`, `deepseek`, `mistral`, `ollama`, `openrouter`, or `openai-compatible`. |
| Provider API keys | Each provider reads its own env: `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `GEMINI_API_KEY`, `AZURE_OPENAI_API_KEY`, `XAI_API_KEY`, `DEEPSEEK_API_KEY`, `GROQ_API_KEY`, `MISTRAL_API_KEY`, `OPENROUTER_API_KEY`, `OPENAI_COMPATIBLE_API_KEY`. Ollama reads `OLLAMA_URL` (defaults to `http://localhost:11434`) and `OLLAMA_API_KEY`. Bedrock reads `AWS_BEDROCK_REGION` and either `AWS_BEARER_TOKEN_BEDROCK` or AWS credentials (`AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`). `openai-compatible` needs `OPENAI_COMPATIBLE_URL` plus a pinned model (see below). |

<Warning>
  **The AI buttons turn on only when the selected provider's key variable is set.** TryPost checks the provider's key, not whether the provider could answer without one. For Ollama, set `OLLAMA_API_KEY` to any value; for Bedrock, use `AWS_BEARER_TOKEN_BEDROCK`; for `openai-compatible`, set `OPENAI_COMPATIBLE_API_KEY` (any value if your endpoint does not check it).
</Warning>

## Pinning a specific model

Each provider ships with a sensible default text model, so setting `AI_TEXT_PROVIDER` and its key is enough to get started. To pin a specific model, set the matching variable:

| Provider | Model variable |
|----------|----------------|
| `openai` | `OPENAI_TEXT_MODEL` |
| `anthropic` | `ANTHROPIC_TEXT_MODEL` |
| `gemini` | `GEMINI_TEXT_MODEL` |
| `azure` | `AZURE_OPENAI_DEPLOYMENT` |
| `bedrock` | `AWS_BEDROCK_TEXT_MODEL` |
| `groq` | `GROQ_TEXT_MODEL` |
| `xai` | `XAI_TEXT_MODEL` |
| `deepseek` | `DEEPSEEK_TEXT_MODEL` |
| `mistral` | `MISTRAL_TEXT_MODEL` |
| `ollama` | `OLLAMA_TEXT_MODEL` |
| `openrouter` | `OPENROUTER_TEXT_MODEL` |
| `openai-compatible` | `OPENAI_COMPATIBLE_TEXT_MODEL` **(required)** |

```env
OPENAI_TEXT_MODEL=gpt-5.4
OPENROUTER_TEXT_MODEL=anthropic/claude-haiku-4.5
ANTHROPIC_TEXT_MODEL=claude-sonnet-5
GEMINI_TEXT_MODEL=gemini-3.6-flash
```

All of these are optional — leave them unset to use the provider's built-in default. `azure` is the exception to the naming pattern: it resolves models via the **deployment name** you create in the Azure portal (`AZURE_OPENAI_DEPLOYMENT`), not a raw model identifier. `openai-compatible` is the other exception: `OPENAI_COMPATIBLE_TEXT_MODEL` is **required**, since an arbitrary endpoint has no sensible default to fall back to.

<Warning>
  **OpenRouter credit pre-checks:** OpenRouter validates your balance against a request's *maximum possible* token usage before generating anything, not the tokens actually used. A low-balance key can fail with `402 insufficient credits` even on a cheap model and a short prompt. Funding the account with a few dollars usually clears this — see [OpenRouter's limits documentation](https://openrouter.ai/docs/api-reference/limits).

  For anything else OpenRouter-specific (available models, pricing, routing behavior), check [OpenRouter's documentation](https://openrouter.ai/docs) directly — TryPost just passes your prompt through.
</Warning>
